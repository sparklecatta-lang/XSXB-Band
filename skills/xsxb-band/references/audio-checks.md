# 试听、排错与导出

先区分用户在听工作室/WAV 还是外部 MIDI。WAV 使用实际录音和效果链，MIDI 只有乐谱及基本 GM 设置；外部播放器用自己的音色，不能用于验证本工具的吉他音色。不要在用户已经说明试听位置后重复追问。

## 最小有效核查

- 检查轨道 muted、solo、volume、音符 velocity、演奏法、起点与范围；再检查音源与启用的箱体 installed 状态、采样 HTTP 响应及解码。
- 使用 `scripts/render.mjs --stems` 导出同一工程的混音和当前可听分轨。不要为了独奏而把 live API 工程改写成一条轨；导出脚本在内存中分轨。
- report 含每轨/整曲 PCM 峰值、RMS、片段峰值、饱和样本数、音频长度与实际样本请求。主乐段 RMS 排除超出谱长的自然尾音；它仍受休止长度影响，不能跨不同乐段直接比较。
- 鼓是瞬态信号，长窗 RMS 偏低不一定听不见；同时看瞬态峰值、同段伴奏电平以及试听。需要时在文件草案里裁出一小段，修正相对起点与末音时值再导出。
- 发现问题后修改声部、选样、包络或效果，再验证对应声部与整段；不要拿“整首波形非零”当作鼓已可听的证明。

缺失录音不使用振荡器或 GM 合成器偷偷兜底；请求下载必须沿用当前用户授权，仅针对要使用的乐器/箱体：

```text
POST http://127.0.0.1:4318/api/instruments/<清单中的ID>/download
Content-Type: application/json

{}
```

等待此请求的时间应允许整件乐器下载；大量分层采样可能超过一般读取接口的 15 秒超时。失败时保留已成功缓存，重试同一资源即可，不先清空库。先确认是否已安装，不重复下载整个目录。

## 导出脚本边界

脚本从指定工作室目录加载真实 `src/audio.ts` / `src/midi.ts`，通过无界面浏览器在本机服务同源页面读取缓存，并使用 OfflineAudioContext 渲染。它复用工作室安装的依赖，不往 skill 附带 node_modules 或音源。

`--project` 可以导出尚未应用到活动工程的草案；导出成功不等于已经保存进工作室。`--out` 必须是尚不存在的目录，避免覆盖旧试听。静音/独奏沿用工程，分轨只包含当前可听且音量非零的声部。JSON 保留所有声部。

若只需要 MIDI/JSON 而没有可解码音源，可使用网页中的独立导出选项；此脚本的 WAV 步骤会明确报错，不假装导出了音频。WAV 总长度可能大于名义谱长，原始镲片等会自然衰减。

标准 MIDI 最多容纳 15 条独立旋律通道。超过时脚本仍导出完整 WAV/JSON，在 report 标明跳过 MIDI；不静默合并不同乐器，也不删轨凑数。

编曲不需要重跑全库校验。只有修改引擎时才按项目规则运行 `npm test`、`npm run build` 和 `node scripts/audio-smoke.mjs` 等相关程序检查。无界面音频检查不是视觉验收，不截图，不替用户评价界面。

交付技术结果与实际听辨结果分别说明。如果无法听音频，明确只完成技术核查，并给用户真实试听文件；不能声称已消除塑料感或已经达到录音室质感。
